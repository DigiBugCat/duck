space scope

The universe everything lives in. One sqlite file + a directory of codex session files. Topics are strings scoped to it; addrs are unique within it.

space/
  atom.db          actors · subscriptions · mailbox · journal
  sessions/        one rollout per decider and per subactor exec
  • Everything is a row or a file. No process exists while the space is quiet.
  • duck is not in the space — attaching = Sub(out:<addr>) + render. A window, not a part.
  • Open: cross-space bridging. Candidate answer: a bridge is just an actor subscribed in two spaces.

actor the entity

The only entity type. A persistent identity that loops through time. At rest it is rows; a revolution is the loop existing for one step.

actors(addr PRIMARY KEY, decider_ref, state_json, session_id)

// life = msgs.foldLeft(actor)(deliver)
// the actor is the machine; the loop is its trace
  • Entity vs execution. Between revolutions the actor is frozen rows — mail accumulates, subactors run, the self doesn't move.
  • Two topics define its surface: in:<addr> (mailbox) and out:<addr> (outbox). Nothing else is addressable.
  • state_json is guard-grade state (thresholds, handles, standing config) — small and structured. Deliberative memory lives in the session rollout.
  • Immortal by default; ends only by emitting Die.

not: a process, a thread, a cron job, a workflow run. All of those are views of this.

decider the identity

The judge between mailbox and outbox. The only component the addr names; the only place course changes. Everything else is buffer, limb, or plumbing.

decider :: (State, Batch) -> (State, List[Effect])

decider_ref resolves to one of:
  llm      claude/codex resume on the actor's session   // a manager
  coded    deterministic script                         // a workflow
  trivial  on tick -> spawn X                           // a routine
  • One revolution = one application. Batch in, effects out, state persisted, sleep. If the decider is an LLM this is realized as one codex exec resume turn; the definition doesn't require a model.
  • Serialization point. All state changes flow through revolutions — no races between steers and results. Revolution frequency = the actor's reaction time.
  • Digests only. The decider ingests batch summaries and subactor results; heavy deliberation burns in subactor contexts. Its memory grows at decision-rate, not thought-rate.
  • Replies are decisions. No stack unwinds across actors. Each revolution freshly chooses what to publish and where; Msg.origin is information, not obligation.

not: a router (subs table routes), a scheduler (clock is a topic), an inbox filter (deleted with the guard).

subactor not a second type

An actor spawned for a task: decider = one exec, lifespan = the task, subscribers = whoever cared at spawn time. Asking a question is spawning one.

ask(question):
  Spawn(addr: fresh, decider_ref: exec(question))
  Subscribe(topic: out:<that addr>)        // scope: its lifetime
// its addr IS the correlation id — one question, one addr, no ambiguity
  • Steer mid-flight: Publish(in:<addr>) → its next revolution kills + resumes the codex session with the steer. Lossless: sessions survive their process.
  • Watchable by anyone. Third parties (duck, logger, sibling) subscribe to the same out-topic without the parent mediating.
  • Terminates by publishing its result, then Die (see invariant 1).

not: an address-less "action"/future — that split existed for thread economics; the pump is a sqlite join and per-task addrs are what make duck-attach work.

mailbox reality in

The topic in:<addr>, materialized as retained rows. The only way reality enters an actor.

mailbox(addr, seq, origin, body, delivered_at NULL)
  • Retain & batch. Nothing is dropped; sleeping through messages converts them into one dense revolution. Seven boring reports arrive as one context.
  • Survives sleep, restarts, reboots. Rows, not process memory — the property Claude Code channels lacks (events drop when the session closes).
  • Ordering within an addr is by seq; cross-actor ordering is not promised.

outbox reality out

The topic out:<addr>. The actor never routes — it speaks here; the subscription table does all delivery.

  • Utterance, not addressing. Parent, asker, window, logger all hear the same speech by subscribing. The decider carries zero routing logic.
  • A directed message still exists: Publish(in:<addr>, body) — an addr is a topic with one subscriber by convention.
  • Keep topics dumb. Strings only. No filtered topics, no transforms, no hierarchies — that's the guard sneaking back in through the plumbing. All intelligence stays in deciders.

msg envelope

The unit of stimulus. Reality enters only as one of these.

Msg { origin: addr | clock | world | human,  body: json }
  • The envelope is the routing. Reply addresses travel in the message; there is no registry of conversations.
  • corr deleted: the asking pattern (spawn a subactor per question) makes the subactor's addr the correlation id.
  • To an LLM decider a batch renders as group chat: [from: mgr-1] "..." — routing intelligence lives in context, not infrastructure.

effect actions as data

The only way reality exits. An ADT, journaled before it is real — every action is inspectable, replayable data first.

Effect = Publish(topic, body)          // speak — incl. directed via in:<addr>
       | Spawn(addr, decider_ref, init)
       | Subscribe(topic) | Unsubscribe(topic)
       | Die(reason)                  // fans out on death:<addr> topic
  • Send deleted — subsumed by Publish. World is arguably Publish to a topic an effector daemon subscribes to; unification deferred.
  • Purity at the boundary: the decider may be nondeterministic inside, but its signature forces every reality-touch through this list.

subscription who hears whom

A row declaring interest. Written only by an actor's own Subscribe effect — the table is a materialization of the actors' declared interests, never edited from outside.

subscriptions(addr, topic)   -- no TTL, no guard

standing   parent → out:<child>          // the org tree
per-ask    asker → out:<subactor>        // scope = its lifetime
window     duck → out:<addr>             // attach
death      anyone → death:<addr>         // supervision, links dissolved
clock      self → clock:<cron>           // a routine is this one row
  • Lifecycle-scoped: subs pointing at a dying actor's topics are GC'd by its Die. No expires column.
  • Guard deleted at this scale: every delivered Msg wakes the decider. Economics moved to pump cadence (global debounce) + publisher-side filtering on the few noisy feeds.

journal the record

Append-only log of every Effect a revolution emitted, written before interpretation. The system's black box and its outbox-of-record.

journal(seq, addr, effect_json, interpreted_at NULL)
  • Data before real. Crash between write and interpret → replay is safe; nothing happens twice ambiguously (interpret is idempotent per seq).
  • The full audit trail of the org is a table scan. The human can always read what every actor did and why it thought so (session id joins to the rollout).

pump the one non-row

A systemd-tick sweep over the tables. The entire runtime; the only thing in the space that is code running rather than data resting.

each tick:
  route      publishers' output × subscriptions → mailbox rows
  deliver    for each addr with undelivered rows: run one revolution
  interpret  journal rows → table mutations (Spawn→actors, Sub→subs,
             Publish→route, Die→GC + death:<addr>)
  • Cadence is the global debounce. A 60s tick batches everything at minute granularity, uniformly, for free.
  • Dumb by construction. Joins and inserts. If the pump needs a policy decision, the design has leaked judgment out of a decider.
  • No daemon: dormant space costs zero. The evict-sweep pattern duck already uses.

dreaming the inward revolution

A revolution with no external stimulus: a slow clock subscription fires, the batch is empty, the decider turns inward.

Sub(clock:daily-3am)  +  empty batch  →  consolidate:
  compact rollout → fresh session with summary
  distill lessons → state_json
  prune dead handles, revise own subscriptions
  • This is the compaction mechanism. Immortal loops accumulate unbounded context; dreaming is the forgetting that makes immortality affordable. Classic actors never needed this — yours remember everything they can't afford to keep.
  • The self modifying the self. The most powerful and most dangerous write in the system: an actor that dreams badly can subscribe itself into a coma or into hypervigilance.
  • Open: what a dream is allowed to rewrite — the one design question with real teeth left.

invariants named rules

  • 1 · deliver-before-Die. The pump flushes ALL of an actor's pending publishes before interpreting its Die — else final answers evaporate with the lifecycle-GC of subscriptions.
  • 2 · topics stay dumb. Strings, rows, joins. All judgment lives in deciders; any smartness in routing is the guard reincarnating.
  • 3 · one writer per table role. subs written only by Subscribe effects; mailbox only by route; actors only by interpret. The human edits via duck → messages, not via UPDATE.

deleted graveyard, with reasons

  • guard — state-dependent wake predicate. Right for 10k actors on firehoses; wrong at dozens-of-actors scale. Economics moved to pump cadence + publisher filtering. Reversible: nullable column on subs.
  • Send — subsumed by Publish; an addr is a topic with one subscriber.
  • TTL / expires — subscription scope became the spawnee's lifetime.
  • corr — the per-question subactor's addr correlates.
  • action/future as a second type — a task is a small actor; watchability wins.
  • links — dissolved into Sub(death:<addr>).
  • route / clock-sweep as parts — they were always just the pump's join and a publisher.
